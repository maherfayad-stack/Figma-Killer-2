# Studio built-in design system — plan

**Status:** proposed and decisions confirmed 2026-09-17. Nothing implemented yet;
ready for wave 1 + wave 2 work orders.

**The ask, in the owner's words:** "we are deleting the design system npm. Have
all the components from it — rather than being in the module — in an Assets
panel in the left panel. Have all those components and the colours right inside
the tool itself so we no longer need to import them. Every component gets a
real preview, not the shimmer thing that makes it harder to find. Add
descriptions and keywords so searching is easier. And the plus that opens the
popup becomes the one that adds a page — new, or one that is already in the
files but was deleted from the board."

This document turns that into file-level work orders. Read
[`PROJECT-BRIEF.md`](PROJECT-BRIEF.md) first; the facts in §1 were verified on
`feat/alm-figma-killer-studio-shell` at `0f480230`.

## 0. Decisions — confirmed by the owner 2026-09-17

All three were confirmed as recommended. They are settled; do not re-open them
in a work order.

1. **Project import shape: the built-in folder.** ✅ Confirmed.
2. **Base elements, layouts and saved components move to Assets too; the popup is deleted.** ✅ Confirmed.
3. **"The plus" is the toolbar `+` at the top.** ✅ Confirmed — it becomes Add page; the Explorer's two page pluses merge into the same picker.

The original options, kept for the record:

1. **How a user's project imports the built-in components once the npm is
   gone.** *Recommended:* Studio writes the design system's **source** into
   every DS-backed project as `<project>/design-system/` (Studio-owned,
   re-synced when stale, never edited by hand — the same contract as
   `prototype/*.generated.*`), and pages import it relatively:
   `import { Button } from '../design-system'`. The downloaded repo then builds
   with only `react` + `vite`, which is the "repository is the document"
   invariant kept honest. *Alternative:* keep the `@alm-design/design-system`
   specifier and have Studio write a `node_modules/` copy plus a `file:` entry
   in `package.json`. Zero changes to existing user source, but `node_modules`
   is excluded from downloads and any `bun install` in the unzipped copy would
   try to fetch a package that no longer exists.
2. **Whether the base elements (container, text, image, button, …), saved
   layouts and saved Visual Components also move into the Assets panel.**
   *Recommended:* yes — they are the other three sections of today's insert
   popup, and the popup is being deleted (CLAUDE.md: no old-and-new). The
   DOM-panel right-click "insert here" menu stays and reads the same model.
3. **Module id prefix.** The design-system components are `alm.<Name>` today.
   *Recommended:* keep `alm.*` — ids are minted at parse time from source, not
   persisted, so a rename buys nothing and touches ~20 tests and every MCP
   tool that names one.

"The plus that opens the popup" is the toolbar `+ Add`
(`ModulePickerDropdown` → `ModuleInserterDialog`, the component popup). It
becomes **Add page**. The two adjacent small pluses in the Explorer's *Pages*
header (`NewPageButton` and `AddFramePicker`) collapse into that same picker.

## 2. Target state, in one paragraph

The ALM design system's **source** lives in the Studio repo at
`vendor/alm-design-system/` and is the only copy Studio renders from — at every
trust tier, with no bundling step, because it is Studio's own code. Every
DS-backed project carries a Studio-written `design-system/` folder so its code
runs and downloads standalone; the parser treats that folder as a black-box
design system (module `alm.<Name>`), never as local components to inline. The
left rail gains an **Assets** panel — design-system components grouped by
purpose, elements, layouts, saved components, icons, colours — every card a
**live render** of the real component with the same seeded props an insert
would write, searchable by name, description, purpose keywords and variant
names. The toolbar `+` and the Explorer's page pluses become one **Add page**
picker: create a Screen / Popup / Bottom sheet, or put a page that already
exists on disk back on the board. The npm dependency, the insert dialog, the
wireframe sketches, and `standing-07`'s "two paths coexist" exception are all
deleted.

## 6. Risks

| Risk | Mitigation |
|---|---|
| The vendored `.jsx` uses Vite `?raw` SVG imports and `.css` side effects | Studio consumes the committed `dist/` (lib build), projects consume `src/` under their own Vite — both already handle it; the freshness gate keeps `dist/` honest |
| Design-system CSS leaks into the admin document via previews | Shadow root + `adoptedStyleSheets` with `:root → :host`; a test asserts the admin `document.styleSheets` never contains a `.btn` rule |
| A user edits `<project>/design-system/` by hand and the canvas (Studio's copy) disagrees with the dev server (their copy) | The folder is Studio-managed and rewritten when stale, with a README saying so — the same contract `prototype/*.generated.*` already has; a hash mismatch is reported in the Dependencies panel rather than silently overwritten *while a file is open* |
| Live previews cost too much on panel open | Lazy mount/unmount by intersection; measured budget: < 16 ms per card mount, < 100 ms panel open on the 70-card set (`perf-hunter` benches it) |
| Overlay components (Dialog, BottomSheet, …) portal out of a shadow root | They stay hidden from Assets — they are page kinds under Add page |
| Third-party design systems (`pkg.*`) lose their sketch and get a "promote" tile | That is the honest Tier-0 state; at Tier 1 the same live-preview path renders them from the bundle |
| Renaming `sourceImport` breaks the MCP `studio_insert` contract | `mcp-tooling` updates `editTools.ts` in the DS-3 PR; e2e `instance-selection-ui.e2e.ts` and `insertJsxElement.test.ts` cover it |
| `bun.lock` churn from removing the npm | One-line dependency change; `bun install` once, commit the lock in the same PR |

## 7. Out of scope, on purpose

- Editing the design system's own components inside Studio (they remain black boxes with props).
- Drag-and-drop from the Assets panel to the canvas (DS-4b, after click-insert ships).
- Typing the vendored `.jsx` as `.tsx` (the manifest carries the prop truth, as today).
- Any change to the `pkg.*` Tier-1 pipeline for third-party packages.
