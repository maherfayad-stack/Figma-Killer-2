## 0. What already exists (do not rebuild)
- P3-C/P3-D/P3-D2/P3-F landed: prop-forwarded text written at the call site, stylesheet auto-pick, style after spread, className wrap, `.map` rows edit the array/template, multi-select as one gesture, expression-child, same-line siblings, restore journal.
- OD-7 is implemented (`instanceOnlyGesture.ts`): detach, replay, linked undo; component-copy fallback (`extractInstanceCopy`).
- Cross-file transplant carries imports (aliasing) and *context-reader* hooks only (`transplantCarry.ts`, `detachHooks.ts`). Everything else in the free-variable set refuses `captured-scope`: `useState/useReducer/useRef`, plain body consts/functions/handlers, props, `.map` item/index.
- `exposeLiteralAsProp` ("Make the text a prop", OD-9) exists but is an opt-in button, one call-site deep, literal text/attribute/inline-style-property only.
- So the remaining pain is not missing machinery; it is that the machinery is opt-in or narrower than the gesture. Three principles for every group below:
  1. The gesture does the Figma thing by default; the consequence is named in a one-line info notice with Undo (journal-backed, byte-exact).
  2. "One honest target" is read as: the write has one place the user *pointed at*, and every other place is provably byte-identical in behaviour (default-preserving prop, independent copy, baked literal). Where that cannot be proven, refuse by name with one remedy.
  3. No flags, no second path: the old refusal branch is deleted in the same change that replaces it.

## 2. Decisions needed from the owner (recommendation first)
- **OD-17 State on a cross-screen/cross-component move.** Rec: YES, move it *with its own independent copy* of the `useState/useReducer/useRef` (initializer must not read captured values; else bake). Info notice: "Moved with its own `value` (starts as `''`). The original keeps its own." Alternative: keep refusing.
- **OD-18 Props and `.map` row values on a move.** Rec: YES, bake the resolved literal (the board already knows it: `resolvedProps` / row sample) as a named `const` at the destination; a function/JSX/object-ref prop that cannot be serialized still refuses, naming it. Moving a row element out of a template is a *copy* of that row (origin template untouched) unless the array is a literal (OD-8 path deletes the item).
- **OD-19 Amend OD-7's second sentence: value edits (text, attr, inline style) inside a shared component become this-instance-only by default**, via auto-added optional prop whose default is the current value (every other instance byte-identical). Toast action "Apply to all (N)"; ComponentSection button "Edit main component" turns on an explicit main-edit mode (banner "Editing Card · all N instances", no per-edit notice). Class-bound styles and nesting deeper than one component keep today's behaviour (write the component + the existing notice) until G2b. This reverses "keep writing to the component" only for the cases the codemod can prove.
- **OD-20 Typing into a code-bound field.** Rec: YES, commit replaces the binding with the literal, info notice "Replaced `{count}` with text. Undo". It is the one place the invariant's "never destroy a binding" yields to explicit intent; Undo restores bytes. Alternative: field stays read-only with an "Unbind" button (one extra click everywhere).
- **OD-21 (open since meta-20) detach of `alm.*`.** Rec: YES. BUILTIN §0.1 makes the design system a Studio-written in-project folder, so it is local code; fix is the id-prefix check in `instanceDetachability.ts`, not an inliner for npm. True `node_modules` packages keep refusing `package-component`.
- **OD-22 (open since meta-21) insert into an instance.** Rec: keep detaching (OD-7 consistency); show a one-line info "Detached Card to place this. Undo restores it" so it is never a surprise.
- **OD-23 Detach hoists state hooks** into the enclosing component when the call site is hook-legal (top level of a component's return, not in a loop/conditional/callback) with fresh names per instance; otherwise the component-copy fallback runs. Rec: YES.
- **OD-24 "Unroll list"** as an explicit, lossy, menu-only action. Rec: YES.
- Doc change with OD-17/18/20: PROJECT-BRIEF invariant 2 gets a sentence: "a write has one honest target, or one named consequence the user is shown and can undo".

## 5. The three that change the feel most
1. **G-1 (a, b, c): moves carry what they read.** Cross-screen drag is the owner's headline gesture and it is the long-toast refusal in the audit (`TextInput` on `useState`, Labels, rows). Do G-1a first (no decision needed), then b and c.
2. **G-2a: editing an instance edits the instance.** 48.5% of corpus nodes sit inside a shared component; every text edit there is currently a blast-radius warning. This is Figma's central model.
3. **G-3: detach and instance-edge gestures never refuse.** Removes the last red outlines and the silent nothing on drag-out/drop-in; also unlocks every state-bearing component.
Quick win alongside: G-4.

## 6. Risks
- Semantics drift on G-1b (state copy is a *behaviour* change) -> always-on notice, journal Undo, initializer must be self-contained, custom hooks refuse by name.
- G-2a doubles the files touched per edit -> uses the existing journaled `expose-prop` kind; Apply-to-all is a CAS restore-compatible edit; add the default-preservation assertion (render other instances before/after) to the test.
- Module size: `transplantJsxElement.ts` is at 696 lines -> new carry code lives in new files only.
- Free-variable classification today is `import|prop`; G-1 needs a finer classifier, and the parser's evaluator tiers must not execute anything (parse only; bake uses already-resolved board values).
- Serial files (`studioEditSchemas.ts`, `studioWriteback.ts`, `studioSourceWrites.ts`) -> one bundle at a time per ROADMAP's serial table.
- Verification: unit tests cannot see these (happy-dom); each bundle needs the real-mouse e2e plus the P3 gesture-sweep with zero `error` toasts and byte-exact undo (see memory "verify plan promises, not tests").
